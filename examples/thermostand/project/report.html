Отчёт по проекту «thermostand»

Версия protoledger 1.0.0. Политики сборки потоков: перекрытия — брать первое, контрольные суммы — предупреждать. Отчёт описывает, что установлено на записях проекта, на чём это основано и чего мы не знаем.

Описание протокола

Длина сообщения — поле в байтах 2–3 (число, 2 байта, старший первым), к значению прибавляется 8; каждое сообщение начинается с A65C.

Статус «установлено» — исследователь подтвердил правило; «предположение» — проверено только на записях проекта и может не выполняться на других данных.

Открытые вопросы

  • q-2: Есть ли у устройства команды кроме 0x10, 0x20 и 0x30? В записях другие коды встречаются только в контрольной отправке клиента, устройство отвечает статусом 1.

Закрытые вопросы:

  • q-1: Порог знаковый или беззнаковый? — Знаковый (i16): отрицательные пороги из журнала совпадают с байтами только при знаковом чтении.

Как воспроизвести

Нужен protoledger версии 1.0.0: статический бинарник для Linux, Windows или macOS либо установщик настольного приложения со страницы Releases репозитория github.com/protoledger/protoledger, или сборка из исходников командой docker compose up --build. Сеть и другие зависимости не нужны.

Проект переносится копированием папки. Результаты перепроверяются командой (код возврата 0 — совпало, 1 — отличия):

protoledger verify <папка проекта>

Описание применяется к новым записям без проекта:

protoledger apply --interpretation <файл> --input <запись>
