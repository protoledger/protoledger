# modbus — протокол с открытой спецификацией

Modbus/TCP — промышленный протокол, спецификация которого опубликована (Modbus Application Protocol 1.1b3, Modbus Messaging on TCP/IP 1.0b). Пример проверяет подход на «чужом» протоколе: описание восстанавливается по записи и журналу действий теми же средствами, что и для «Термостенда», а затем сверяется с документом. В коде движка о Modbus нет ни строки — всё описание лежит в `interpretation.yaml`.

| Файл | Что внутри |
|---|---|
| `session.pcap` | Два соединения с устройством на порту 502: панель оператора опрашивает регистры и входы по кругу; инженерная станция читает и пишет регистры и катушки, получает отказы, запрашивает сведения об устройстве |
| `actions.csv`, `mapping.yaml` | Журнал действий инженерной станции (16 действий): время, действие, параметры и результат в JSON |
| `interpretation.yaml` | Описание протокола: фрейминг, 11 видов сообщений, 12 предположений с проверками, 3 структурные проверки |
| `expected/apply-session.json` | Результат `protoledger apply` |
| `generate.mjs` | Генератор записи и журнала: кадры собираются по спецификации, сеть и устройство не нужны |

Запись содержит то, на чём обычно спотыкается разбор по пакетам: ответ, пришедший двумя сегментами, и два запроса в одном сегменте.

## Что находится по одним данным

| Шаг | Результат |
|---|---|
| Границы сообщений | Первый кандидат — длина `u16` старшим байтом вперёд по смещению 4, размер сообщения = значение + 6; 72 сообщения, расхождений нет. Равнозначные варианты названы рядом: `u32` по смещению 2 (перед длиной всегда два нуля) и `u8` по смещению 5 (длины меньше 256) |
| Изменчивость байтов | Из 36 запросов 33 имеют размер 12 байт; в них байты 2–6 постоянны (`00 00 00 06 01`), байт 1 меняется от запроса к запросу |
| Связи с журналом | В запросах чтения регистров `address` из журнала совпадает с `u16` по смещению 8, `count` — с `u16` по смещению 10 (7 из 7); байт 7 однозначно делит действия `read_holding` и `read_input` |
| Пары запрос→ответ | В соединении станции 16 пар: 14 однозначных и 2 сопоставленных по порядку — два запроса, ушедших одним сегментом; порядок здесь допущение, и оно так и помечено |

## Сверка со спецификацией

| Поле описания | Предположение, проверенное на записи | В спецификации |
|---|---|---|
| `transaction` | H1: ответ повторяет номер запроса | Transaction Identifier |
| `protocol` | всегда 0 | Protocol Identifier, 0 = Modbus |
| `length` | размер сообщения = значение + 6 | Length: число байт после поля, включая адрес устройства |
| `unit` | H2: ответ повторяет адрес | Unit Identifier |
| `function` | H3: ответ повторяет код, при отказе — код + `0x80` | Function Code; Exception: код со старшим битом |
| `address`, `quantity` | H4, H5: совпадают с параметрами действия | Starting Address, Quantity of Registers |
| `byte_count` | H6: два байта на регистр; H7: байт на 8 катушек | Byte Count |
| `registers` | H10: первое значение совпадает с результатом в журнале | Register Value, старший байт первым |
| `coil_value` | H9: `0xFF00` включить, `0x0000` выключить | Output Value: `FF 00` = ON, `00 00` = OFF |
| `exception_code` | H11: совпадает с кодом из журнала | Exception Code: 1 — функция, 2 — адрес, 3 — значение |

Все 12 предположений выполняются на записи без расхождений. Это совпадение на примерах, а не доказательство: например, порядок битов внутри байта катушек (H7) записью проверяется только через число байт.

Не описано намеренно: функция `0x2B` (сведения об устройстве). Заголовок разобран, 24 байта тела помечены как неизвестные — частичное описание остаётся рабочим.

## На чужой записи

Описание проверено и на записи, которую делали не мы: `4SICS-GeekLounge-151021.pcap` из открытого набора 4SICS (ICS-лаборатория конференции 4SICS 2015, публикует Netresec: https://www.netresec.com/?page=PCAP4SICS), 139 998 821 байт, sha256 `7365b0ea475b76bf79b207fd8f83baa45e4449aead5da6a9214bbcffbc5fa7de`. В репозиторий запись не кладём: это чужие данные.

| Что | Результат, protoledger 1.0.0 |
|---|---|
| Соединения Modbus/TCP | 29 соединений на порту 502: 58 потоков из 200 000 попадают в область описания, остальные — S7, HTTP, telnet и другой трафик |
| Сообщения | 19, все совпали с описанием, нарушений нет |
| Что в них | 13 запросов функции `0x2B` (сведения об устройстве; тело намеренно не описано, заголовок разобран) и 6 отказов на неё (`0xAB`); чтения и записи регистров в записи нет |
| Предел | В записи больше 100 тыс. соединений: разобраны первые 100 тыс., 59 748 кадров сверх предела отмечены диагностикой `limit_exceeded`, а не отброшены молча |

Журнала действий к этой записи нет, поэтому предположения, которые сверяются с журналом, остаются без примеров.

```bash
protoledger apply --interpretation examples/modbus/interpretation.yaml --input 4SICS-GeekLounge-151021.pcap > /tmp/apply-4sics.json
```

## Повторить

```bash
protoledger apply --interpretation examples/modbus/interpretation.yaml \
  --input examples/modbus/session.pcap \
  --action-log examples/modbus/actions.csv --mapping examples/modbus/mapping.yaml \
  > /tmp/apply-session.json
diff /tmp/apply-session.json examples/modbus/expected/apply-session.json && echo совпало

node examples/modbus/generate.mjs    # пересоздать запись и журнал: файлы не меняются
```

То же описание применимо к любой другой записи Modbus/TCP: условие области — порт 502.
