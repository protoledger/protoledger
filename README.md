# protoledger

Лаборатория для исследования недокументированных бинарных протоколов поверх TCP: от записей трафика к проверяемому и переносимому описанию обмена.

![Экран «Протокол»: сообщения и поля протокола, найденные по записям и журналу действий, с проверкой на записях](docs/img/protocol.png)

## Какую задачу решает

Подключить систему к устройству без документации на протокол — обычная задача интеграции: промышленные контроллеры, измерительные приборы, медицинское и торговое оборудование, IoT, устаревшие сервисы. Обычно это Wireshark, hex-редактор, заметки и одноразовые скрипты: выводы не привязаны к данным, не проверены на других записях и не передаются коллеге.

protoledger превращает записи обмена (PCAP/PCAPNG) и журнал действий в штатном клиенте в описание протокола, которое:

- **проверяемо** — каждый вывод привязан к конкретным байтам конкретной записи, противоречия видны как расхождения на конкретных сообщениях;
- **повторно применимо** — то же описание запускается на новых записях одной командой, без ручной работы;
- **переносимо** — исследование хранится в папке проекта и воспроизводится на другой машине.

## Для кого

| Кто | Зачем |
|---|---|
| Инженер-интегратор | Найти команды и значения в обмене устройства и получить описание для реализации |
| Разработчик драйвера, шлюза, эмулятора | Машиночитаемое описание, примеры и автоматическая проверка реализации |
| Инженер поддержки и QA | Понять, что изменилось после обновления прошивки или клиента |
| Руководитель, подрядчик | Передать и принять исследование вместе с основаниями выводов |

## Цикл работы

1. **Открыть записи** — файлы .pcap/.pcapng и журнал действий (.csv). Соединения и потоки собираются по TCP; повторы, потери, обрезанные кадры и неверные контрольные суммы видны явно.
2. **Составить описание** — одной кнопкой: границы сообщений, коды команд, поля и их связь с действиями оператора. Каждое поле — «установлено», «предположение» или «не описано».
3. **Проверить** — на всех записях и на новой записи без правки описания; несовпадения — с конкретными байтами и строкой журнала.
4. **Исправить** — программа перебирает варианты (знак, порядок байтов, ширина, масштаб) и показывает, какой убирает расхождения; новая версия описания проверяется заново.
5. **Передать** — отчёт со спецификацией протокола, файл описания для программ, папка проекта, команда повторного применения.

Тот же цикл шаг за шагом со скриншотами — [docs/guide.md](docs/guide.md).

Работает локально и офлайн: настольное приложение, интерфейс в браузере на localhost и командная строка.

## Быстрый старт

Требования: Linux x86-64, Docker с Compose v2, git.

```bash
git clone --recursive https://github.com/protoledger/protoledger.git
cd protoledger
cp .env.example .env
docker compose up --build
```

Интерфейс: http://localhost:8080.

### Без Docker: готовый бинарник

На странице [Releases](https://github.com/protoledger/protoledger/releases) — архив `protoledger-<версия>-linux-x86_64.tar.gz`: статический бинарник, интерфейс встроен, библиотеки и сеть не нужны.

```bash
tar -xzf protoledger-*-linux-x86_64.tar.gz
./protoledger serve --workspace ~/protoledger
```

Интерфейс: http://127.0.0.1:8080. Там же — сборки для Windows и macOS (`.zip`, `.tar.gz`) и `SHA256SUMS`.

### Настольное приложение

В Releases — установщики: Windows `.msi`, Linux `.deb` и AppImage. Приложение запускает движок внутри себя и открывает интерфейс в своём окне; проекты по умолчанию — в папке `~/protoledger` (на Windows — `C:\Users\<имя>\protoledger`).

- Windows: установщик не подписан — в окне SmartScreen «Подробнее» → «Выполнить в любом случае».
- Linux: нужен WebKitGTK 4.1 (`sudo apt install libwebkit2gtk-4.1-0` в Debian и Ubuntu 22.04+); AppImage — `chmod +x protoledger_*.AppImage && ./protoledger_*.AppImage`.

### Командная строка

`protoledger apply` применяет описание протокола к новой записи без проекта, `verify` перепроверяет перенесённый проект, `report` собирает отчёт — подробнее в [docs/requirements.md](docs/requirements.md#как-повторить-проверку-руками).

Описание API — `API.md` и `openapi.yaml` в [репозитории движка](https://github.com/protoledger/protoledger-backend); Swagger UI есть только в dev-сборке ([docs/dev.md](docs/dev.md)).

## Как пользоваться

Пример — набор организаторов «Термостенд»: записи обмена клиента с измерительным устройством и журнал действий оператора. Протокол считается неизвестным. В приложении он открывается кнопкой **«Открыть пример»** на стартовом экране; файлы лежат в `examples/thermostand/sample_protocol`.

![Стартовый экран: открыть записи или пример](docs/img/start.png)

**1. Записи.** Импорт идёт в фоне; для каждой записи видно число кадров, соединений и замечания к захвату: повторы, пропуски, обрезанные кадры, контрольная сумма, которую считала сетевая карта.

![Записи и замечания к захвату](docs/img/capture-defects.png)

**2. Протокол.** «Составить описание» — программа находит, где начинается и кончается сообщение (здесь — сигнатура A6 5C и длина в байтах 2–3), какой байт задаёт команду, и связывает поля с параметрами из журнала. Для каждого поля — байты, как их читать, что они означают, результат проверки и статус.

![Сообщения и поля протокола](docs/img/protocol.png)

**3. Проверка на новой записи.** Запись, которой не было при составлении описания, разбирается тем же описанием без правки: 16 сообщений из 16.

![Проверка на дополнительной записи](docs/img/new-record.png)

**4. Ошибка и исправление.** Если поле прочитано неверно (здесь порог как число без знака), проверка показывает расхождения на конкретных сообщениях — отрицательный порог −2,5 °C. «Как исправить» находит вариант, который их убирает, и проверяет его на всех записях.

![Расхождения по полю порога](docs/img/mismatch.png)

![Подсказка исправления: читать как число со знаком](docs/img/fix.png)

**5. Отчёт.** Описание протокола таблицами, где и на чём проверено, что осталось неизвестным; скачивается в HTML и Markdown, описание — файлом для программ.

![Отчёт: описание протокола](docs/img/report.png)

То же из командной строки:

```bash
S=examples/thermostand/sample_protocol
protoledger draft --input $S/research/01_configuration.pcap --input $S/research/02_variations.pcapng \
  --input $S/research/03_combined_messages.pcap \
  --action-log $S/action_journal.csv --mapping examples/thermostand/mapping.yaml --out draft.yaml
protoledger apply --interpretation examples/thermostand/interpretation.yaml \
  --input $S/additional/04_new_observations.pcapng \
  --action-log $S/action_journal.csv --mapping examples/thermostand/mapping.yaml
protoledger verify examples/thermostand/project/thermostand.protoledger
```

## Демо

- Весь сценарий прогоняется автоматически: браузер нажимает те же кнопки, что человек, и снимает каждый шаг — `docker compose up --build -d`, затем `bash e2e/run.sh` ([docs/dev.md](docs/dev.md#демо-сценарий-в-браузере)).
- Презентация проекта — [docs/presentation.pdf](docs/presentation.pdf).
- Готовый проект с этим исследованием — `examples/thermostand/project`: открывается в приложении кнопкой «Открыть сохранённый проект».

| Путь | Что |

| `Dockerfile`, `compose.yaml` | сборка и запуск |
