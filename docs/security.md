# Безопасность и надёжность

protoledger работает с недоверенными данными — записями обмена неизвестного устройства, журналами, чужими проектами и описаниями протоколов — и поднимает HTTP-сервер на локальной машине. Поэтому любой ввод считается враждебным. Ниже — что защищается, какими мерами и чем каждая мера проверена.

## Что защищаем

| Что | От чего |
|---|---|
| Исходные записи и их целостность | повреждённый или специально собранный файл записи |
| Достоверность результатов | чужой проект, описание протокола или журнал с подвохом |
| Машина пользователя: файлы и память | сайт в браузере пользователя, который обращается к `localhost` |
| Содержимое записей (в трафике бывают пароли и персональные данные) | другие пользователи системы и сеть |
| Доступность: не падать и не зависать | данные, рассчитанные на исчерпание памяти и времени |
| Сборка, которую скачивает пользователь | зависимости и CI |

## Меры и чем они проверены

Тесты названы так, как они называются в коде движка ([protoledger-backend](https://github.com/protoledger/protoledger-backend)); все они выполняются в CI при каждом изменении.

### Разбор записей

| Угроза | Мера | Проверка |
|---|---|---|
| Падение на кривых длинах и заголовках | В разборщиках запрещены `unwrap`, `expect`, индексация без проверки и `panic` (линтер, уровень `deny`); `unsafe` запрещён во всех крейтах. Ошибка кадра — диагностика кадра, импорт продолжается | `corrupted_bytes_never_panic`, `every_prefix_of_a_file_is_handled`, `hostile_samples_match_expected_outcomes` |
| Заявленная длина «4 ГиБ» | Длина сверяется с остатком файла и с пределом до выделения памяти | `no_giant_allocation_on_declared_lengths` |
| Скачок номера последовательности TCP | Поток — список участков; дыра хранится как метаданные, байты под неё не выделяются | `seq_jump_becomes_a_gap_not_bytes`, `seq_jump_of_half_the_space_is_ignored_safely` |
| Сотни тысяч соединений, тысячи перекрытий | Пределы с явной ошибкой `limit-exceeded`, без молчаливого обрезания | `large_records_hit_limits_or_finish_in_time`, `connection_limit_is_reported_as_problem` |
| Файл не является записью, пуст, обрезан | Проверка сигнатуры и типа (только обычные файлы), предел размера | `not_a_capture`, `file_size_limit`, `rejects_non_capture_and_leaves_no_temp_files` |
| Зависание без обратной связи | Долгие операции — задачи с прогрессом и отменой | `cancellation_stops_import`, `delete_cancels_running_job` |
| Непредвиденная ошибка роняет сервер | Каждая задача изолирована: сбой превращается в ошибку задачи, сервер продолжает отвечать | `panic_becomes_failed_job`, `every_hostile_file_is_handled_and_server_stays_alive` |

### Проект на диске

| Угроза | Мера | Проверка |
|---|---|---|
| Пути наружу: `..`, абсолютные пути, символические ссылки | Пути внутри проекта только относительные и нормализованные; ссылки не разыменовываются | `parent_dir_in_path_is_rejected`, `symlinked_manifest_is_not_followed` |
| Подменённая или удалённая исходная запись | Копия записи хранится под именем своего sha256 и только читается; при открытии хеш сверяется | `tampered_or_removed_copy_is_detected`, `verify_detects_a_modified_source_copy` |
| Подправленный результат проверки | `protoledger verify` выполняет прогон заново и сравнивает с сохранённым | `verify_detects_a_tampered_result` |
| Повреждение проекта при сбое | Запись атомарная: временный файл в папке проекта и переименование | `research_documents_are_replaced_atomically`, `cancellation_stops_copy_and_cleans_up` |
| Огромный или «взрывной» YAML | Предел размера; якоря и ссылки YAML запрещены, глубина ограничена | `yaml_bomb_and_huge_manifest_are_limited`, `interpretation_input_is_validated` |
| Выражения в описании протокола | Собственный интерпретатор без доступа к файлам, сети и процессам; предел шагов (10 тыс.) и вложенности (32) | `evaluation_errors_do_not_panic`, тесты `pl-interp` |
| Доступ других пользователей системы | Linux: папка проекта `0700`, файлы `0600` | `project_files_are_private` |

### Локальный API

| Угроза | Мера | Проверка |
|---|---|---|
| Порт виден в локальной сети | Движок слушает только `127.0.0.1`; в Docker порт публикуется только на `127.0.0.1` хоста | `compose.yaml` |
| Подмена имени хоста (DNS rebinding) | Заголовок `Host` — только `127.0.0.1`, `localhost`, `[::1]`; иначе `403` | `foreign_host_is_forbidden_everywhere`, `loopback_hosts_are_accepted` |
| Сайт в браузере вызывает API (например, импорт `~/.ssh/id_rsa` и чтение байтов) | Токен сессии (256 бит, новый при каждом запуске) в заголовке `X-Protoledger-Token`; движок отдаёт его только своей странице. Проверка `Origin`, заголовков CORS нет | `every_contract_endpoint_requires_token`, `foreign_origin_is_forbidden`, `tokens_differ_between_sessions` |
| Проверка состояния без токена | Только `/api/health`: отдаёт статус и версию, `Host` и `Origin` проверяются | `health_needs_no_token_but_checks_host` |
| Встраивание страницы, подмена типа содержимого | `Content-Security-Policy: default-src 'self'; frame-ancestors 'none'; object-src 'none'; base-uri 'none'`, `nosniff`, `no-referrer` | `security_headers_on_every_response` |
| Огромные тела запросов, лавина задач, вечные подписки | Тело JSON до 8 МиБ, загрузка — до предела файла записи, не больше двух долгих задач, поток событий задачи не дольше 30 минут | `oversized_json_body_is_rejected`, `oversized_upload_is_rejected_without_leftovers`, `concurrent_limit_is_enforced` |
| Инструменты разработки в поставке | Swagger и режим разработки собираются только с cargo-feature `dev-tools`; в поставке этого кода нет | `docs_exist_only_in_dev_build`; CI ищет следы в собранном бинарнике (`check-release-clean.sh`) |

### Интерфейс и отчёт

| Угроза | Мера | Проверка |
|---|---|---|
| Разметка и скрипты из содержимого пакетов, журнала, имён полей | Строки из данных выводятся только как текст; `v-html` запрещён линтером (`vue/no-v-html: error`); управляющие символы и переключатели направления письма заменяются видимыми метками | `safe-text.test.ts`, `hostile_strings_are_returned_as_data_not_markup` |
| Разметка в отчёте | HTML-отчёт: всё из данных экранировано, скриптов и внешних ресурсов нет, `Content-Security-Policy` в `<meta>`; в Markdown разметка экранируется | `html_escapes_everything_from_data`, `markdown_does_not_break_tables_or_inject_markup` |
| Утечка содержимого записей | Продукт работает офлайн: нет телеметрии, внешних шрифтов, CDN и сетевых запросов. В журнал работы пишутся идентификаторы, длины и смещения, но не содержимое пакетов | — |
| Содержимое пакетов как программа | Данные записей не исполняются, не распаковываются, не передаются внешним программам и не отображаются как HTML или изображения | — |

### Настольное приложение

Окно показывает только встроенный движок на `127.0.0.1` со случайным свободным портом. Переход на любой другой адрес блокируется (`navigation_stays_on_engine`), политика содержимого та же, что у сервера. Расширений с доступом к файлам, командной оболочке, сети или обновлениям приложение не подключает.

### Сборка и зависимости

| Мера | Где |
|---|---|
| Зависимости только из lock-файлов; `cargo deny` (уязвимости, лицензии, источники — только crates.io) и `pnpm audit --prod` в CI | CI движка и интерфейса |
| Пакеты npm: скрипты установки разрешены только пакетам из явного списка, версии моложе суток не ставятся | `pnpm-workspace.yaml` интерфейса |
| CI с минимальными правами (`contents: read`), без `pull_request_target` | workflows |
| Образ Docker: многоэтапная сборка, не root, корневая файловая система только для чтения, без capabilities, `no-new-privileges`; запись — только в папку проектов | `Dockerfile`, `compose.yaml` |

## Злые записи и мутации

`examples/hostile/` — 37 намеренно кривых файлов: не записи, обрезанные и битые контейнеры pcap и pcapng, невозможные длины в заголовках IPv4 и TCP, скачки и переполнение номера последовательности, тысячи перекрытий и соединений, HTML и управляющие символы в данных. Для каждого файла в `expected.json` записан ожидаемый итог — ошибка или число кадров, сегментов, соединений и диагностика. Проверяется дважды: на уровне разборщиков и через API (сервер после каждого файла продолжает отвечать).

Мутационный тест `mutated_real_captures_never_panic` портит настоящие записи (случайные байты, обрезка, вставки) и проверяет, что разбор не падает: 1500 мутаций в каждом прогоне CI, длинный прогон — `FUZZ_ITERATIONS=200000 cargo test -p pl-hostile --release mutated_real`.

Сборка потоков сверяется с независимой реализацией: `streams_match_tshark_follow` сравнивает собранные потоки с `tshark -z follow,tcp,raw` на записях, где результат однозначен (порядок по номерам последовательности, повторы, неверные суммы, длинные ответы на десятки сегментов). В CI этот тест обязателен.

## Защитные пределы

Все пределы и их значения — в [limits.md](limits.md). Превышение — явная ошибка с именем предела и значением.

## Граница модели

Программа, запущенная от имени того же пользователя или администратора, имеет те же права, что и protoledger: она читает файлы проекта, память процесса и может узнать токен сессии. Защититься от неё на уровне приложения нельзя — как и любому локальному инструменту. protoledger не ухудшает положение: данные лежат только в папке проекта, права — только пользователя, сети нет, содержимое записей не попадает в журналы и временные файлы. Для чувствительных записей рекомендуем шифрование диска средствами операционной системы.

## Чего сознательно нет

| Чего нет | Почему |
|---|---|
| Шифрования проекта на диске | От программы с правами пользователя при открытом проекте не защищает, зато мешает переносу и командной строке. Точка расширения — слой хранения проекта |
| Экспорта и импорта архивом | Проект — папка: перенос — копирование и `protoledger verify`. Нет распаковки — нет атак через архивы |
| Экспорта в CSV | Не нужен сценарию; нет и инъекций в таблицы |
| Подписанных установщиков | Установщики не подписаны: при запуске Windows покажет предупреждение SmartScreen |
| Блокировки проекта от двух экземпляров | Атомарной записи достаточно, чтобы файл не оказался повреждённым |
