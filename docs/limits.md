# Ограничения и замеры

## Защитные пределы

Записи, журналы и проекты считаются недоверенным вводом. Каждый предел — именованная константа в коде движка; превышение — явная ошибка `limit-exceeded` с именем предела и значением, данные молча не обрезаются.

| Предел | Значение |
|---|---|
| Размер файла записи (pcap, pcapng) | 1 ГиБ |
| Кадров в одной записи | 10 млн |
| Соединений в одной записи | 100 тыс. |
| Сегментов с данными в одном направлении | 1 млн |
| Записанных байтов одного направления | 512 МиБ |
| Размер сообщения | 16 МиБ |
| Сообщений в одном потоке | 1 млн |
| Файл описания протокола (YAML) | 4 МиБ |
| Шагов вычисления выражения / глубина вложенности | 10 тыс. / 32 |
| Файл журнала действий / строк в нём | 256 МиБ / 1 млн |
| Поле журнала / колонок / вложенность и число значений JSON в ячейке | 64 КиБ / 256 / 16 и 1024 |
| Одновременных долгих задач (импорт, прогон) | 2 |
| Байтов потока в одном ответе API | 1 МиБ |
| Элементов на странице списка в API | 500 |
| Тело JSON-запроса к API | 8 МиБ |
| Сообщений в одном прогоне проверки / контрпримеров, которые он хранит | 2 млн / 1000 |
| Наблюдений, гипотез, вопросов в проекте (каждого вида) | 20 тыс. |
| Подсказки по границам: байтов на поток / на запрос, потоков на запрос, время поиска | 1 МиБ / 16 МиБ, 64, 20 с |
| Изменчивость байтов: сообщений в анализе / байтов в столбцах сообщения | 100 тыс. / 4096 |
| Связи с журналом действий: сообщений в анализе | 5 тыс. |
| Поиск контрольной суммы: сообщений / размер сообщения / байтов на запрос | 2 тыс. / 64 КиБ / 16 МиБ |
| Типы сообщений и подсказки полей: сообщений в анализе | 20 тыс., поровну между потоками запроса |
| Сдвиг часов журнала: наибольшая поправка / точность / действий в оценке | 14 ч / 10 мс / 2000 |
| Соединения устройства по журналу: соединений в ответе | 500 (устройство — первыми; всего — в `total`) |
| Просмотр потока SSE (прогресс задачи) | 30 минут |

## Обязательная область

Ethernet (до двух VLAN-меток), IPv4, TCP. Сверх обязательного читаются записи без заголовка Ethernet: Linux cooked (так пишет `tcpdump -i any`), raw IP и петлевой интерфейс macOS и BSD. IPv6, фрагменты IPv4, другие транспорты и прочие канальные уровни не разбираются: такие кадры пропускаются с диагностикой, остальная запись обрабатывается.

## Замеры

Профиль проверки — 100 МиБ, 250 тыс. пакетов, 1000 соединений на 4 vCPU / 8 ГиБ.

Замер 15.10.2026 — workflow `bench` движка 0.3.0 на раннере GitHub Actions: Linux x86-64, 4 vCPU, память движка ограничена 8 ГиБ, сборка `release`. Запись профиля — 99,3 МиБ, 250 160 кадров, 1000 одновременных соединений, 235 410 сообщений; четверть нагрузки — ответы от 16 до 64 КиБ, каждый разрезан на кадры по 1400 байт.

Командная строка (`protoledger bench`, лучшее из пяти повторов):

| Операция | Время |
|---|---|
| Чтение файла | 19,6 мс |
| Индексация кадров (Ethernet, IPv4, TCP, контрольные суммы) | 81,9 мс |
| Сборка 2000 направленных потоков | 67,0 мс |
| Применение описания: границы и разбор 235 410 сообщений | 33,3 мс |
| Всего | 0,20 с (590 МиБ/с на разбор) |

Пик памяти процесса — 171 МиБ (`VmHWM`): запись читается в память целиком, данные пакетов не копируются.

Путь интерфейса (`scripts/bench-api.mjs`: движок как в приложении, запросы к его API):

| Операция | Время |
|---|---|
| Импорт записи в проект: копия, sha256, индекс, сборка 1000 соединений | 0,80 с |
| Прогон описания по всем сообщениям с двумя гипотезами и сохранение прогона | 0,78 с |
| Отчёт Markdown / HTML | 0,02 с / 0,02 с |

Пик памяти движка за весь путь — 200 МиБ. Замер на отдельной виртуальной машине с тем же профилем не проводился: раннер GitHub Actions — те же 4 vCPU.

Как измерить (из каталога `backend/`; запись профиля создаётся детерминированно, за секунды):

```bash
cargo run -p pl-synth --release -- profile --out bench-data/profile.pcapng
protoledger bench bench-data --interpretation fixtures/synthetic/interpretation.yaml --repeat 3
```

Команда печатает время чтения файла, индексации кадров, сборки потоков и применения описания, скорость разбора и пик памяти процесса (на Linux).

Путь интерфейса — тем же файлом профиля (нужен Node.js 18+; `--memory-gib` — предел памяти движка через `prlimit`, только Linux):

```bash
node scripts/bench-api.mjs target/release/protoledger bench-data/profile.pcapng --memory-gib 8
```
