# Ограничения и замеры

## Защитные пределы

Записи, журналы и проекты считаются недоверенным вводом. Каждый предел — именованная константа в коде движка; превышение — явная ошибка `limit-exceeded` с именем предела и значением, данные молча не обрезаются.

| Предел | Значение |
|---|---|
| Размер файла записи (pcap, pcapng) | 1 ГиБ |
| Кадров в одной записи | 10 млн |
| Соединений в одной записи | 100 тыс. |
| Сегментов с данными в одном направлении | 1 млн |
| Записанных байтов одного направления | 512 МиБ |
| Размер сообщения | 16 МиБ |
| Сообщений в одном потоке | 1 млн |
| Файл описания протокола (YAML) | 4 МиБ |
| Шагов вычисления выражения / глубина вложенности | 10 тыс. / 32 |
| Файл журнала действий / строк в нём | 256 МиБ / 1 млн |
| Поле журнала / колонок / вложенность и число значений JSON в ячейке | 64 КиБ / 256 / 16 и 1024 |
| Одновременных долгих задач (импорт, прогон) | 2 |
| Байтов потока в одном ответе API | 1 МиБ |
| Элементов на странице списка в API | 500 |
| Тело JSON-запроса к API | 8 МиБ |
| Сообщений в одном прогоне проверки / контрпримеров, которые он хранит | 2 млн / 1000 |
| Наблюдений, гипотез, вопросов в проекте (каждого вида) | 20 тыс. |
| Подсказки по границам: байтов на поток / на запрос, потоков на запрос, время поиска | 1 МиБ / 16 МиБ, 64, 20 с |
| Изменчивость байтов: сообщений в анализе / байтов в столбцах сообщения | 100 тыс. / 4096 |
| Связи с журналом действий: сообщений в анализе | 5 тыс. |
| Поиск контрольной суммы: сообщений / размер сообщения / байтов на запрос | 2 тыс. / 64 КиБ / 16 МиБ |
| Типы сообщений и подсказки полей: сообщений в анализе | 20 тыс. |
| Просмотр потока SSE (прогресс задачи) | 30 минут |

## Обязательная область

Ethernet (до двух VLAN-меток), IPv4, TCP. IPv6, фрагменты IPv4, другие транспорты и канальные уровни не разбираются: такие кадры пропускаются с диагностикой, остальная запись обрабатывается.

## Замеры

Профиль проверки — 100 МиБ, 250 тыс. пакетов, 1000 соединений на 4 vCPU / 8 ГиБ.

Замер 12.10.2026 — workflow `bench` движка на раннере GitHub Actions: Linux x86-64, 4 vCPU, память процесса ограничена 8 ГиБ, сборка `release`, лучшее из пяти повторов. Запись профиля — 99,3 МиБ, 250 000 кадров, 1000 одновременных соединений, 244 000 сообщений.

| Операция | Время |
|---|---|
| Чтение файла | 42,5 мс |
| Индексация кадров (Ethernet, IPv4, TCP, контрольные суммы) | 82,7 мс |
| Сборка 2000 направленных потоков | 66,3 мс |
| Применение описания: границы и разбор 244 000 сообщений | 48,7 мс |
| Всего | 0,24 с (519 МиБ/с на разбор) |

Пик памяти процесса — 160,7 МиБ (`VmHWM`): запись читается в память целиком, данные пакетов не копируются.

Это замер командной строки. Через интерфейс к нему добавляются копирование записи в проект с подсчётом sha256 и сохранение прогона. Замер на отдельной виртуальной машине с тем же профилем ещё не проводился.

Как измерить (из каталога `backend/`; запись профиля создаётся детерминированно, за секунды):

```bash
cargo run -p pl-synth --release -- profile --out bench-data/profile.pcapng
protoledger bench bench-data --interpretation fixtures/synthetic/interpretation.yaml --repeat 3
```

Команда печатает время чтения файла, индексации кадров, сборки потоков и применения описания, скорость разбора и пик памяти процесса (на Linux).
